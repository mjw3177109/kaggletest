## V2.5｜对标高手的 GPU 优化（小白版）

问题：为什么 0.95819 仍排名靠后？答案不只是模型不够大，
很多强手把同一条航线距离、同一客群服务评分的细粒度规律显式提供给模型。

**V2.5 改进三点：**
1. 全 21 个原始字段的精确值做 5 折交叉拟合 Target Encoding，严格防止标签泄漏。
2. 用精确 Flight Distance 分组构造航线画像、同出行群评分交互。
3. 比较 LightGBM、GPU XGBoost 和固定权重融合的 3 折 ROC-AUC。

提醒：GPU XGBoost 只占用 Kaggle T4 的一个 CUDA 设备，
LightGBM 在同一 Notebook 的 CPU 端训练，没有假冒 GPU 加速。

该比赛尚未启动 V2.5 实验。

详细研究资料：competitions/connectx/v25_peer_research.md
V2.5 实验报告：reports/v2_5_latest.md。

## V2.7｜不占 GPU 配额的 OOF 双模型融合（小白版）

这一版不是重新训练新模型，而是把我们已经得到的 V2.5 和 V2.6 折外预测进行固定 50/50 排名融合。
只会读取自己 Kaggle Notebook 保存的 OOF 和提交预测；不使用别人的答案、私榜标签或测试集真实标签。
两版必须使用相同 3 折分组、相同训练标签和完全一致的测试 ID 顺序，任何不一致立即停止。
V2.7 的 CV 必须超过已验证最佳 CV 0.00010 才可能提交，且会先确认今天的 Kaggle 提交限额。

当前比赛尚未执行 V2.7，不影响旧冠军和 TPU 分支。

完整结果：reports/v2_7_latest.md
