## 2. Kaggle 高手的核心策略

**先赢验证、再赢模型。** 此次数据为合成信用卡欺诈表格数据，AUC 是概率排序指标。欺诈阳性占比只有约 1.67%，因此不能以 Accuracy 或单次随机分割排名。训练必须有足够的阳性验证样本、模型间真正互补性、可靠的组/近重复审查，以及训练/测试分布一致性判断。

### P0：比赛数据研究与验证设计（尚未完成）

1. 逐列识别数值、布尔、类别、高基数变量，核对类型与单位、异常/极端值；检查是否存在代理目标、由标签定义的特征或字段时间顺序风险。
2. 审核训练-测试偏移：类别支持域、分位数、频率、缺失/常数列、极端尾部差异；不把由 \`id\` 引出的任何规律默认视为可泛化信号。
3. 在**正式目标编码前**检查去 ID 后完全重复行、近重复、同特征不同标签；若确实存在同实体重复，则预注册 GroupKFold 分组策略。数据只有 \`time_of_day_hour/day_of_week\` 等周期字段，**不能仅凭它们声称存在跨月份时间戳**。
4. 预注册主评分为 5 折 \`StratifiedKFold\` ROC AUC（种子固定且记录每折欺诈样本数），保留备用的分组/时间验证方案，发现分布结构证据才切换；新验证方案不能事后迎合 Public LB。
5. 增加独立 holdout 或嵌套验证专门评估特征筛选和 stack 权重，不在同一套 OOF 上过量反复优化。记录逐折分数、预测 OOF 覆盖率与 bootstrap 置信区间。

### P1：强基线与公平横向比较（数据研究过门后执行）

- **B0 LightGBM**：正确处理类别与数值、CPU 5 折，折内独立预处理，固定版本/随机种子；报告各折 ROC AUC、平均及方差，不用 Public LB 当优化器。
- **B1 CatBoost**：按类别原生处理，固定同一批 fold/row ID，与 B0 配对评估；关注样本不平衡和泛化误差。
- **B2 XGBoost**：\`hist\`、合理正则化/早停；同 fold 同样验收，使模型间差异可归因。
- 早停必须只观察对应训练/验证折的数据；目标编码与特征筛选必须位于外层训练折内，OOF 每条样本只由未见过其标签的模型产生。
- 三种模型的**官方数据集**、fold membership、样本顺序、代码提交 SHA、环境依赖和模型 checkpoint 必须可追溯，不出现 CV/文件错位。

### P2：特征和模型互补性（仅在证明边际增益时增加）

候选方向不是预先宣称有效：将交易金额、距离、交易频度、商家风险、VPN/跨境/设备渠道/认证方式、AI 欺诈标志等域信息分组；验证合理比率和交互，而不是盲目制造成千上万维。对强相关/疑似代理标签列做消融；只报告有独立折级证据的提升。

适度探索 RealMLP/TabM、小规模 GPU 实验，**每个新增模型必须用相同样本 ID 的独立 OOF 证明与现有树模型互补**。预训练 TabPFN 等权重需先核许可证、参赛可及性与算力，不默认采用。公开其他队伍的 OOF、原始相似数据、非 Kaggle 外部数据一律暂不引入；必要时再单独做规则/来源审计。

### P3：冲榜融合与独立验收

- 先做等权平均或 rank 平均的朴素对照，再考虑 logit 融合；复杂二层模型须用嵌套 CV 学权重，避免 S6E10 同一套 OOF 搜权造成的乐观偏差。
- 仅在**配对逐折及 bootstrap**显示合理、方向稳定的边际增益时进入下一候选；提升非常小而不稳定则不增加模型/计算量。
- 提交格式：299,984 行，\`id,is_fraud\` 列序，ID 与官方测试集完全对齐，预测有限且在 [0,1]，无缺失、无重复。
- 记录候选文件 SHA256、所有基模型训练/推理文件来源、训练代码版本、模型版本、实验条件、逐折 ROC AUC、融合权重及独立 OOF 验收报告。
- 正式提交前：Kaggle 实时加入状态 + 规则 SHA + 剩余额度 + 截止时间 + GitHub 全仓库 Actions 五态 + 唯一提交预约；SHA 已提交不得再提交。
- 每场默认**一个**正式主提交；只有预注册策略和强证据支持时使用第二次。Public LB 不作为优化权重的训练集。
