### 7.3 冠军路线 vs 本队 V2915：技术差距是什么

| 维度 | 本队 V2915（已认证历史记录） | 官方冠军 writeup 披露 | 可迁移结论 |
|---|---|---|---|
| 主体模型 | 树模型 + RealMLP 的固定比例融合，三折 OOF CV 0.961285 | **GPT-2 将字段写成文本，target-first 学习 `P(features | label)`**，再通过贝叶斯比值分类 | **数据生成机理建模**可能优于继续细调同质模型；不是每个数据集都适用 |
| 验证 | 3 folds、固定 blend、阈值式准入 | 统一 5 折 OOF、logit 转换 + L2 LogisticRegression 二层堆叠 | 统一 OOF split、校验 row ID、使用嵌套二层验证，禁止在同一 OOF 上反复搜权 |
| 多样性 | 相对少量模型与特征 | 公开 245 个 OOF/test 配对 → 再加入 GPT/TFM，总计 259/332 成员两个备选 | 数量本身不是收益；先检验新成员**边际增益**与来源/许可 |
| 报告指标 | **Public 0.96099**；最终 Private 未知 | 冠军披露 245 对堆叠 CV 0.96218/Public 0.96186，259 对堆叠 CV 0.96290/Public 0.96262 | **不同团队的 CV/Public 不是可直接等价的最终 Private 结果** |
| 资源预算 | 现有免费/授权算力优先 | 冠军称 GPT-2 small 单折约 **2 小时 A100**，另需原始数据预微调与多模型训练 | 不把冠军 A100 路线写成可在免费配额内直接复现；先评估合规性/显存/时限 |

冠军文档还解释了为什么 label-first 方案在本次比赛格外有效：作者从 GPT-2 tokenizer/采样分布推断 Playground 合成数据来自 GReaT 类生成过程，`P(features | label)` 正好近似逆向建模该生成器。**这是冠军作者的机制假设和实验结论，不等于已独立证明 Kaggle 官方实际生成配方。** 对真实信用卡欺诈数据不能照搬生成机理。

### 7.4 真正读到的公开源码：实现细节及问题

1. **`src/te_proper.py`**：外层 `StratifiedKFold(5)`，内层 sklearn `TargetEncoder(smooth="auto", cv=5)`；训练折 `fit_transform`，验证/测试折 `transform`，这个**目标编码隔离模式值得借鉴**。但现有源码调用 `LGBMClassifier.fit(..., eval_X=..., eval_y=...)`，与常见 LightGBM sklearn 接口的 `eval_set=[(X_val,y_val)]` 不符；需在锁定版本环境中验证后修复，**不可宣称原样可复现**。
2. **`src/route_profile.py`**：精确 `Flight Distance` 分组生成折内均值、标准差、残差、类别占比；折内频次/稀有度编码；目标编码仅使用外层训练折并做内层交叉拟合。其外部原始数据 XGBoost 特征依赖额外数据来源与许可，且 `REAL` 路径硬编码本地 Windows 绝对路径；在另一比赛复用前必须验收许可/来源、抽取配置并重新检验 OOF。
3. **`src/te_cond_freq.py`**：条件 target encoding、数值分组 target encoding、内层频率 crossfit，与 LightGBM/XGBoost/CatBoost 的 OOF 集成。仍使用 `eval_X/eval_y` 风格 LightGBM 调用；脚本末尾在整份 OOF 上遍历 blend 权重求最大 AUC，**有融合权重的选择偏差风险**，不能用该优化分数直接作为独立泛化增益。
4. **`src/tabm_route.py`**：保留 10 折、折内目标编码，与航线特征融合的 TabM 是模型多样性来源；GPU 资源和依赖适配需要实际测量，不作为默认零成本方案。
5. **`src/fusion.py`**：源码是**早期** 2/3 路融合脚本，存在 `TabM OOF 无法直接算`、以近似数值展示的说明；该仓库 README 也注明不是最终 30/30/40 融合的完整可执行脚本。因此不能把这个文件当作完整冠军复现程序。
6. **独立复现记录**：该其他团队记录了 RealMLP 配置改进、深层 XGB 和权重搜索在 Public 上的反转。是其公开报告的实验数字，**不是本队 Kaggle API 可验证的提交**；但“同一 OOF 上优化 blend 会高估”与我们的安全验收方向一致。

### 7.5 4090 能做、不能直接做的事情（留给下一场合规实验）

- Koumei Maki 的 S6E10 实测：Windows RTX 4090 + TabPFN-3.5，调整 SDPA backend 后作者报告预测吞吐约 **25 → 2385 行/秒**、五折约 **42 分钟**、峰值显存约 **17.4 GB**。这只证明**作者指定软件/检查点/数据规模**下的表现；不要在未经版本/授权审查时直接覆盖本地 ComfyUI 或其他生产环境。
- 外部基础模型/OOF 预测文件必须检查竞赛规则、商业/非商业授权、队伍外成果共享的许可和折划分一致性；严禁复用 S6E10 的标签、权重或模型到无关 S6E11 数据。
- 第一优先：低成本 LightGBM/CatBoost/XGBoost 基线 + 明确的 Train/Valid ID 对齐、固定 random seed 和 fold-local 全流程。
- 第二优先：只在 **S6E11 规则许可并有数据可用**后，实验正确的内层目标编码、异构模型 OOF 和严格 nested-stack；先做两折筛选，再决定是否值得 5 折。
- 第三优先：可选免费 GPU 配额做 TabPFN/RealMLP 的**小规模**验证；不能满足许可证、显存、时长或复现实验门禁则跳过。
- 第四优先：任何强模型/新融合必须给出独立逐折增益、方差及来源；Public LB 只做外部 sanity check，不作为权重调参集。不得为了逼近榜首动用付费 A100、不可复核的公开预测或私有标签。
